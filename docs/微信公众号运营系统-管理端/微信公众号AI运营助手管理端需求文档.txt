# 微信公众号AI运营助手管理端需求文档

**版本：** V1.1 精简版  
**对应用户端需求：**《微信公众号AI运营助手轻量版需求文档 V1.2》  
**作者：** Manus AI

---

## 一、管理端是做什么的

管理端供平台内部人员使用，主要负责配置AI能力、维护官方技能、管理用户、查看公众号连接和处理后台失败任务。

管理端不参与用户具体写作。管理员配置好模型、提示词和技能后，用户在用户端直接与AI对话；后台自动读取当前有效配置完成文章生成、修改、保存和公众号发送。

> **简单来说：用户端负责使用，管理端负责提供能力和保证能力正常运行。**

## 二、管理端有哪些模块

| 管理模块 | 管理端有什么 | 与用户端的联系 |
|---|---|---|
| 管理首页 | 用户、AI调用、公众号和失败任务概况 | 帮助管理员发现哪些问题正在影响用户 |
| AI配置 | 模型供应商、模型、模型路由和提示词 | 决定用户每次对话调用什么模型、AI如何生成文章 |
| 官方技能库 | 官方技能的新增、修改、测试、发布和停用 | 发布后进入用户端技能库，用户可以启用和选择 |
| 用户管理 | 用户资料、账号状态、使用量和资源额度 | 决定用户能否登录、生成文章、上传资料和绑定公众号 |
| 公众号管理 | 微信平台配置、已绑定公众号和连接状态 | 决定用户能否绑定公众号、写入草稿和正式发布 |
| 任务管理 | AI生成、文件解析、草稿和发布任务 | 管理员可以处理失败任务，用户端同步看到最新结果 |
| 系统设置 | 首页示例、文件限制、功能开关和管理员账号 | 控制用户端显示什么、允许做什么以及公共使用限制 |

## 三、管理首页

管理首页用于快速查看系统是否正常，不需要做复杂数据分析。

| 页面内容 | 显示什么 | 管理员可以做什么 |
|---|---|---|
| 用户概况 | 用户总数、今日活跃用户、新增用户 | 进入用户管理查看详情 |
| AI运行 | 今日生成次数、成功率、平均耗时、当前异常模型 | 进入AI配置或任务管理 |
| 公众号运行 | 正常连接、需要重新连接、草稿或发布失败数量 | 进入公众号管理 |
| 失败任务 | AI、文件解析、草稿和发布的失败数量 | 进入任务管理处理 |
| 最近配置 | 最近发布的模型路由、提示词和官方技能 | 查看当前生效版本 |

## 四、AI配置

AI配置由四部分组成：**模型供应商、模型、模型路由和提示词**。

### 4.1 模型供应商

模型供应商用于配置平台接入的大模型服务，例如腾讯混元或其他兼容服务。

| 功能 | 管理员操作 | 用户端变化 |
|---|---|---|
| 添加供应商 | 填写名称、接口地址和API Key | 暂时没有变化，供应商需要配置模型后才能使用 |
| 测试连接 | 检查接口和密钥是否可用 | 测试不会影响用户使用 |
| 启用供应商 | 允许模型路由使用该供应商 | 新的AI请求可以调用该供应商的模型 |
| 暂停供应商 | 暂停新的模型请求 | 系统改用路由中的备用模型 |
| 替换API Key | 输入新密钥并重新测试 | 测试成功后继续提供AI能力，用户无须重新登录 |

API Key保存后不显示完整内容，只显示是否已配置和最近更新时间。

### 4.2 模型管理

管理员在供应商下添加平台实际要使用的模型。

| 模型信息 | 说明 |
|---|---|
| 模型名称 | 管理端显示名称 |
| 模型标识 | 调用供应商接口时使用的model值 |
| 模型类型 | 对话模型、Embedding模型或Rerank模型 |
| 模型能力 | 是否支持流式输出、图片理解和结构化输出 |
| 使用场景 | 对话、文章生成、文章修改、检查、摘要或偏好总结 |
| 最大输入与输出 | 限制单次请求可以处理的内容长度 |
| 调用价格 | 用于统计AI成本 |
| 状态 | 测试中、可用或暂停 |

新模型需要先执行测试。测试通过并设置到模型路由后，用户的新请求才能使用它。暂停模型不会改变已经生成的文章，正在执行的任务继续使用开始时确定的模型。

### 4.3 模型路由

模型路由决定不同任务使用哪个模型。用户端不需要自己选择模型。

| 用户操作 | 管理端配置的路由 | 后台运行方式 |
|---|---|---|
| 普通对话或选题讨论 | 对话路由 | 使用响应较快的对话模型 |
| 生成完整文章 | 文章生成路由 | 使用长文生成模型 |
| 修改文章 | 文章修改路由 | 结合当前文章和修改要求调用模型 |
| 检查文章 | 内容检查路由 | 检查结构、引用和明显错误 |
| 总结会话 | 摘要路由 | 生成任务上下文摘要 |
| 总结写作偏好 | 偏好总结路由 | 对比用户确认前后的文章形成偏好 |
| 检索参考资料 | Embedding和Rerank路由 | 将资料向量化并选出相关片段 |

每条路由设置一个主模型和一个备用模型。主模型临时调用失败时，后台自动尝试备用模型，用户端只显示“正在重试”。

管理员修改路由后先保存，再点击发布。发布后只影响新的AI请求，正在生成的文章不切换模型。

### 4.4 提示词管理

提示词管理用于配置AI在不同阶段应该做什么。主要包括：

| 提示词 | 作用 | 用户端表现 |
|---|---|---|
| AI基本规则 | 规定AI的职责和边界 | AI不会假装读取失败的资料，也不会自行发布文章 |
| 意图识别 | 判断用户是讨论、写文章、改文章还是生成标题 | 用户用自然语言输入即可，不需要选择复杂菜单 |
| 文章生成 | 组合要求、技能、偏好和资料生成正文 | 决定文章的结构和生成方式 |
| 文章修改 | 处理全文修改或选中段落修改 | 用户说“改一下开头”即可修改对应内容 |
| 结果检查 | 检查资料引用、结构和明显错误 | 生成完成前显示“正在检查内容” |
| 偏好总结 | 从用户最终确认的文章中总结习惯 | 后续生成更符合用户习惯 |

管理员可以编辑提示词、使用测试内容运行、查看结果并发布。发布后新的AI请求使用新版本；如果效果不好，可以恢复上一版本。

## 五、官方技能库

官方技能是平台提供给用户的写作方法，例如文章生成、深度改写和资料总结。

| 功能 | 管理员操作 | 用户端变化 |
|---|---|---|
| 新建技能 | 填写名称、简介、适用场景和写作要求 | 草稿状态下用户看不到 |
| 测试技能 | 输入测试要求并查看生成结果 | 不影响用户正在使用的技能 |
| 发布技能 | 确认技能内容并发布 | 技能出现在用户端“官方技能”中 |
| 修改技能 | 创建新版本并重新测试 | 发布后新的AI请求使用新版本 |
| 调整排序 | 设置技能在用户端的显示顺序 | 用户技能列表顺序发生变化 |
| 暂停技能 | 暂停新的调用 | 用户不能再选择，历史文章和任务不变 |
| 恢复技能 | 重新启用已暂停技能 | 用户可以再次启用和选择 |

用户在用户端启用官方技能后，AI才能自动选择该技能；用户也可以在对话输入框中手动指定。一次创作只使用一个主要技能。

## 六、用户管理

用户管理用于查看用户账号、使用情况和当前可用额度。

| 功能 | 管理员操作 | 用户端变化 |
|---|---|---|
| 查看用户 | 按手机号、用户ID、状态或注册时间搜索 | 没有变化 |
| 查看使用量 | 查看AI用量、存储、文件和公众号数量 | 没有变化 |
| 调整额度 | 修改AI额度、存储、单文件大小和公众号数量 | 用户后续操作按照新额度校验 |
| 限制AI生成 | 暂停该用户发起新的AI请求 | 用户仍可查看和编辑已有文章 |
| 暂停公众号功能 | 暂停草稿和发布操作 | 用户仍可继续创作和保存文章 |
| 禁用账号 | 禁止登录并退出已有设备 | 用户不能继续登录，但数据不会删除 |
| 恢复账号 | 恢复用户账号 | 用户可以重新登录和继续使用 |

用户详情显示基本信息、最近登录、使用量、绑定公众号和失败任务。管理员默认不查看用户文章正文、对话全文和原始资料。

## 七、公众号管理

公众号管理分为平台接入和用户已绑定公众号两部分。

### 7.1 微信平台配置

管理员配置第三方平台AppID、AppSecret、回调地址、消息Token和EncodingAESKey，并查看票据和Token是否正常。密钥保存后不显示完整内容。

平台配置正常时，用户可以扫码绑定公众号；平台配置异常时，管理端提示影响的是新增绑定、草稿同步还是正式发布。

### 7.2 已绑定公众号

| 管理端内容 | 管理员可以做什么 | 用户端变化 |
|---|---|---|
| 公众号列表 | 查看名称、所属用户、连接状态和授权时间 | 用户端显示相同的连接状态 |
| 权限状态 | 检查是否具备草稿和发布能力 | 用户端只显示“正常”或“当前不支持该功能” |
| Token状态 | 查看最近刷新结果，必要时重新刷新 | 刷新成功后用户可以继续发送 |
| 授权失效 | 标记需要重新连接 | 用户下次发送时看到重新绑定提示 |
| 最近任务 | 查看草稿和发布的成功或失败记录 | 用户端同步显示最终结果 |

管理员只能维护连接和处理异常，不能代替用户发布文章。

## 八、任务管理

任务管理用于查看后台正在执行或已经失败的任务。

| 任务类型 | 来源 | 管理员能看到什么 | 管理员能做什么 |
|---|---|---|---|
| AI生成任务 | 用户发送对话或修改要求 | 当前阶段、模型、耗时和错误 | 查看、取消未完成任务或重新生成 |
| 文件解析任务 | 用户上传文件或网页链接 | 上传、解析、OCR和向量化状态 | 重新解析或标记文件不可用 |
| 偏好总结任务 | 用户保存、发送草稿或发布文章 | 是否已经完成偏好总结 | 重新执行总结 |
| 草稿同步任务 | 用户发送公众号草稿 | 图片处理、草稿创建或更新状态 | 对明确失败的任务进行重试 |
| 发布任务 | 用户确认正式发布 | 提交、处理中、成功或失败 | 查询最终状态；明确失败后才能重试 |

管理员处理任务后，用户端自动更新对应状态。任务重试不会新建一份用户文章，也不会删除原来的失败记录。

如果系统不能确定公众号是否已经创建草稿或提交发布，管理端先执行“核对结果”，不能直接再次发送，避免产生重复草稿或重复发布。

## 九、系统设置

| 设置项 | 管理员可以配置什么 | 用户端变化 |
|---|---|---|
| 创作首页 | 欢迎语和示例指令 | 用户进入AI创作页时看到新内容 |
| 文件设置 | 支持格式、单文件大小和链接抓取开关 | 用户上传时按照新规则校验 |
| AI设置 | 最大追问数量、文章长度和偏好功能默认开关 | AI按新规则回答和生成 |
| 文章设置 | 自动保存间隔和历史版本数量 | 编辑器保存与版本显示发生变化 |
| 公众号设置 | 草稿和发布开关、图片限制 | 用户端显示或隐藏相应操作 |
| 功能开关 | 开启或关闭某项用户功能 | 用户端入口和后台校验同步变化 |
| 管理员账号 | 添加、停用和修改管理端账号 | 不影响普通用户账号 |

系统设置保存后需要点击发布。发布成功后用户下一次打开页面或发起请求时使用最新设置。

## 十、管理端与用户端如何联动

| 用户端动作 | 管理端提供的内容 | 后台如何处理 | 用户得到的结果 |
|---|---|---|---|
| 用户输入写作要求 | 模型路由、提示词和已启用技能 | 选择模型并组装本轮上下文 | AI回复或生成文章 |
| 用户上传文件 | 文件格式和大小设置 | 上传、解析、OCR和检索 | 文件状态变为已读取或读取失败 |
| 用户选择官方技能 | 已发布的官方技能版本 | 把技能写作要求加入本轮提示词 | 文章按该技能生成 |
| 用户保存文章 | 偏好总结模型和提示词 | 对比修改前后版本 | 形成个人或项目写作偏好 |
| 用户发送公众号草稿 | 微信平台配置和公众号连接 | 转换图片并创建或更新草稿 | 用户看到草稿结果 |
| 用户正式发布 | 微信平台配置和发布任务 | 提交发布并持续查询结果 | 用户看到处理中、成功或失败 |
| 用户操作失败 | 任务管理 | 自动重试或由管理员处理 | 用户端更新为最新状态 |

整个运行关系可以概括为：

> **管理端配置能力 → 后台读取当前配置 → 用户端发起操作 → 后台执行 → 用户端展示结果 → 管理端查看运行情况并处理异常。**

## 十一、主要页面

| 页面 | 主要内容 |
|---|---|
| 管理员登录 | 账号、密码和验证码 |
| 管理首页 | 用户、AI、公众号和失败任务概况 |
| AI配置 | 供应商、模型、模型路由和提示词 |
| 官方技能库 | 技能列表、编辑、测试和发布 |
| 用户列表与详情 | 用户资料、状态、使用量和额度 |
| 公众号列表与详情 | 平台配置、账号连接和近期任务 |
| 任务列表与详情 | 任务阶段、错误、重试和最终结果 |
| 系统设置 | 首页、文件、AI、文章、公众号和功能开关 |
| 管理员账号 | 管理端账号的新增、停用和修改 |

## 十二、验收标准

| 验收内容 | 通过标准 |
|---|---|
| 添加模型 | 供应商连接测试通过后可以添加模型 |
| 发布模型路由 | 新AI请求使用新路由，正在运行的任务不受影响 |
| 发布提示词 | 新请求使用新版本，可以恢复上一版本 |
| 发布官方技能 | 用户端技能库能够看到并启用该技能 |
| 暂停官方技能 | 用户不能新选该技能，历史任务不变 |
| 调整用户额度 | 用户下一次操作按照新额度校验 |
| 禁用用户 | 用户已有设备退出，用户数据仍保留 |
| 公众号异常 | 管理端和用户端显示一致的连接状态 |
| 重试失败任务 | 用户端得到最新状态，不产生重复文章或重复发布 |
| 修改系统设置 | 用户端入口、限制和提示与管理端发布值一致 |

## 十三、总结

管理端只需要管清楚七件事：**系统现在是否正常、AI用什么模型和提示词、平台提供哪些官方技能、用户能使用多少能力、公众号是否正常连接、失败任务如何恢复、用户端公共设置是什么。**

这些配置统一由后台读取并作用到用户的新操作中，既保证用户端简单，也保证平台能够持续维护AI能力和处理运行问题。
