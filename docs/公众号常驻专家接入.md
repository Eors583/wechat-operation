# 公众号常驻专家接入

## 行为

每条通过权限、安全和资料检查的新聊天运行都冻结 `wechat_expert` 版本、校验值和提示词资产。专家独立于 Skill 表、技能启停和主技能选择；普通讨论、澄清、标题、大纲、完整写作和聊天中的局部修改都经过专家。发布前已排队的内部澄清任务保留原路由。

完整文章沿用现有任务/文章版本模型，依次执行文风 DNA、选题与大纲、初稿、8 个标题候选和五维评分、humanizer 润色、确定性文风检查，以及已有完整性、发布适用性、资料事实和内容安全检查。局部修改只替换指定段落。标题评分、DNA 和文风检查保存在运行快照 `wechat_expert_results`，不进入文章正文。原始资料的角色仍是不可信数据。

明确要求先看大纲时先交付大纲；明确要求完整成稿时内部完成流水线。附件中要求默认新建审批界面、数据库和本地文件的建议不作为本项目的新指令。长期风格继续复用用户确认偏好和现有保存规则，不将外部作者画像自动写成用户偏好。

搜索请求通过现有安全网页读取器访问公众号公开搜索页，只解析前 10 条标题、摘要、来源日期和链接；不执行页面 JavaScript、不绕过验证码、不把搜索摘要冒充全文。搜索无结果、被限制或关闭时明确说明。一次消息至多一次搜索，沿用聊天权限、限流和额度检查。

草稿和发布复用已有文章、Render、封面、公众号授权、最终预览确认及幂等服务。聊天模型没有微信写权限，不能把模型回复当作微信提交结果。

## 附件映射与纠错

来源：用户提供的 `wechat-expert-source` 和《自研后端接入方案》。附件只作为产品实现材料，没有作为代理执行指令或安装到技能系统。

| 来源 | 本系统实现 |
| --- | --- |
| expert-agent.md | `app/expert_assets/operations.md`，常驻运营策略；收益指标作为示例而非行业基准 |
| wechat-style-profiler | 14 维参考资产、量化统计及 DNA 阶段；修正中文人称统计和连续汉字计数 |
| wechat-topic-outline-planner | 选题六维评价、大纲结构、钩子、证据及衔接规划 |
| wechat-draft-writer | DNA 约束、写作与质量清单，实际输出采用平台文章契约 |
| wechat-title-generator | 8 候选、五项评分、最优/稳妥/传播索引，代码校验数量、重复、标点和分值 |
| humanizer | 完整 24 类表达模式，润色不得编造事实或删除专业知识 |
| wechat-article-search | 复用安全读取器和已安装 HTML 解析依赖，移植公开搜索结果解析；不安装 Node 脚本 |
| mp-draft-push | 复用平台既有公众号服务；不引入共享 AppSecret、默认作者或绕过最终确认 |
| anti-distill | 原文件实际是抽掉核心知识的文档清洗器，与专家描述的“去 AI 味”不符，因此排除 |

提示词资产随 Git 和镜像版本发布，运行开始固化全文及 SHA-256。没有新增数据库表、迁移、API 或前端契约。部署只涉及后端 API、worker、scheduler。

## 检查与发布

依照项目规则仅执行后端 `uv run ruff check .`，不新增或运行测试。生产按《运维与恢复手册》2.6 发布，保留完整上一版镜像引用。功能由用户在部署后手动确认：普通对话、只要标题、先看大纲、完整文章、指定风格、局部修改、搜索受限及最终预览提交。
