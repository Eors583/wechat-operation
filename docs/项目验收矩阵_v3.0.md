## 1. 当前结论

仓库内可实现的业务代码、接口契约、迁移、自动化测试、构建脚本、容器编排、监控配置、备份脚本和跨项目验收链路已经落地。当前状态是“代码实现完成，发布验收未完成”，不能标记为生产交付完成。

尚未完成的内容都依赖仓库外部条件：真实 Git/Submodule 元数据和远程仓库、可运行的 Docker Linux Engine、生产第三方账号与密钥、正式域名和 TLS、Windows/Android/iOS 签名材料、macOS/Xcode 与真机、100—300 条真实检索问题、20—200 路模型配额及压测环境、安全扫描/渗透测试、备份恢复演练和告警接收通道。任何 Mock、静态配置解析或无签名安装包都不能替代这些上线证据。

状态定义：

- `通过`：本机已有可复现的执行结果。
- `已实现`：代码和自动化门禁已提交，但本机缺少对应外部运行环境。
- `外部待验收`：必须由部署、账号、签名、真机、真实数据或生产基础设施提供结果。

## 6. 生产交付阻塞项

以下项目全部取得证据后，才可以回答“项目已完成”：

1. 在真实母仓库和三个子仓库中创建并推送确定提交，`git submodule status --recursive` 无 `-`、`+`、`U`，`release-manifest.json` 成功生成且工作区干净。
2. 在 CI 或部署主机运行 `compose.test.yml`，完成 PostgreSQL、pgvector、Redis、RabbitMQ、MinIO、ClamAV、API 和 Worker 集成；再按运维手册做一次可计时的备份恢复演练。
3. 接入全部生产 Provider 和 Secret Manager/KMS，用真实模型、Embedding、Rerank、短信、内容安全、对象存储、文件解析、版式和微信账号完成沙箱/灰度验收。
4. 准备正式域名、TLS 和微信 OAuth/消息回调，验证回调签名、授权续期、草稿、发布、失败和 UNKNOWN 对账。
5. 在受控性能环境运行 k6 的 API、文章库、SSE、上传、Worker 和 AI profiles；AI 分别验证 20、50、100、200 并发及 RPM/TPM、队列、额度和成本。
6. 使用 100—300 条真实人工标注问题运行 `scripts/retrieval_benchmark.py`，取得权限泄露 0、Recall@10 ≥ 90%、纯检索 P95 < 300ms、完整检索 P95 ≤ 2000ms 的报告。
7. 在 Windows、Android 和 Apple 平台配置正式签名；完成 Windows 安装/升级/卸载、Android 真机、iPhone/iPad 真机、Universal Link/OAuth 回跳和安全存储测试。
8. 运行依赖/镜像/代码安全扫描、权限与注入测试、受控渗透测试，并关闭所有高危问题。
9. 接通 Prometheus/Grafana/Loki/Tempo/OTel 和真实告警接收人，验证模型失败、队列堆积、微信异常、数据库容量、备份失败和证书过期告警。
10. 由产品、开发、测试、安全和运维共同签署用户端、管理端、微信、数据隔离、性能、恢复和发布回滚验收记录。
