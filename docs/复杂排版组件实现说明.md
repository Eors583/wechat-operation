# 复杂排版组件：方案评估与实现

## 方案取舍

采用“语义角色 + 样式 + 可替换参数 + 关系”的方案，复用既有
LayoutComponentGroup 和不可变模板版本，不另建平行模板体系。

参考文档中的样本尺寸、署名行数和识别率是外部输入，不视为本项目的实测验收结果。
无 alt 不等于视觉模型不能识别数字；同尺寸图片家族也不等于必然是章节标识。
家族和相邻短标题用于形成候选，实际数字由视觉输入确认，不能按图片出现顺序猜测。

## 已接入的处理

- 保留经过数字格式校验的原图宽度、宽高比和裁剪元数据，向排版智能体提供家族证据。
- 右对齐署名按至少两行标签/值、总长度和正文标点约束识别，不依赖顶层 DOM。
  模板保留字段标签及标签/值样式，原作者姓名留空，必须填写自己的信息才能启用。
- 导语卡片和正文引用卡片独立分类；保留上右下左内边距，渲染新文章的首段或引用，
  不复制来源正文。固定像素容器宽度不照搬，使用响应式宽度约束。
- 章节图片按 sequence 映射，不按上传顺序映射；支持 PNG/JPG 上传、替换、移除和改号。
  单图小于 1 MB，图片总量受 5 MB 约束。上传素材引用服务端 document ID，不保存 blob URL。
- 展示素材仍核对归属、文件哈希、格式及安全扫描，不依赖 OCR 或检索索引完成。
- 最终渲染从固定微信图片 CDN 读取来源序号图片，强制 HTTPS、不跟随重定向、限制大小、
  并发和总等待时间，并带微信 Referer。成功读取的图片嵌入不可变排版快照。
- 保存微信草稿前，把快照内嵌图片上传为微信正文图片 URL，不把 data URL 直接交给草稿接口。
  不增加草稿创建、文章保存或发布的自动重试。
- 缺图默认提示补齐，可显式选择使用当前实际章节的文字序号；绝不循环套用上一张图。
- 跨账号或来源账号无法匹配时默认使用文字序号，保留原图映射供用户显式切换。

## 明确边界

没有可靠设计规范时不自动逆向重绘品牌徽标，采用原图保留或用户选定的文字降级。
图片序号由用户上传时，章节号是用户明确指定的值，不声称上传时进行了 OCR。
已保存的旧模板不会被静默重识别；重新提取创建的新版本才使用新版识别逻辑。
引用卡片应用到语义引用节点，不能保证从普通正文中自行推断所有引用语义。

本次按项目规则仅运行 lint 和上线所需本地构建，不运行文档中的真实样本验收、
模型调用、浏览器测试或微信写入测试。识别召回率和视觉还原度仍待用户功能验收。
