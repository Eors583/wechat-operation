## 新结构

`user_memory_entries` 的一条记录对应一个用户、一个项目作用域和一个偏好维度：

- `user_id`、可空的 `project_id`、`key`：归属、作用域、维度。
- `value`、`evidence`：偏好内容和用户原文依据。
- `status`、`source_type`：生效/撤销和确认来源。
- `source_message_id`、`confirmation_message_id`、`source_at`：来源追溯。
- `id`、`created_at`、`updated_at`：记录身份和更新时间。

个人作用域对 `(user_id, key)` 建部分唯一索引，项目作用域对
`(user_id, project_id, key)` 建唯一约束，防止 NULL 作用域下产生重复记录。
项目引用不使用 `ON DELETE SET NULL`，避免项目偏好意外变成全局偏好。

`preference_proposals` 使用来源消息 ID 作主键；保存用户、项目、维度、建议内容、
依据、状态、过期时间、建议时间及确认来源。`base` 和 `previous_value` 是确认时的
冲突检测及展示快照，不属于无用重复字段。主键保证一条来源消息只有一条建议。

两张表使用外键、状态约束和与当前查询匹配的索引。账户注销清理同时清理新表。
智能体仅读取本人已确认的生效记录，仍按“当前输入 > 写作风格 > 用户偏好”使用。
同维度项目偏好优先于全局偏好，不向前端提供完整偏好档案。

消息表中的单轮/批次评估进度仍是本轮任务元数据，暂不另建通用工作流表。
确认建议通过接口投影回原有消息响应结构，前端和 OpenAPI 契约不变。

## 迁移与兼容窗口

迁移：`e8c20f7a913b`，前置版本：`d7f93a10bc62`。

1. 在目标镜像交付并准备好后，暂停 API、Worker、Scheduler 的写入，备份业务库。
2. 从目标镜像单独执行 Alembic 升级；创建两张表，回填旧偏好和历史建议。
3. 迁移遇到未知字段、无效日期、重复维度、外键/状态错误或计数不一致时中止事务，
   不静默丢弃旧记录，不切换应用。
4. 持久化目标镜像仓库和版本，再切换三个后端服务，恢复网关。

旧 `user_preference_memories.items` 和消息里的 `preference_proposal` **本阶段仍保留**，
作为上一版应用的回滚副本，新应用在同一事务内同步写入；它们不再是新应用的读取来源。
本阶段不宣称已经删除这些冗余存储，也不删除文章、聊天、发布或审计数据。

应用回滚只切回上一镜像，无需数据库降级。迁移的 downgrade 明确拒绝删除新表。
**如果旧版恢复运行并接收了写入，再次启用新版本前必须暂停写入，从旧副本重新回填并
核对新表；不能直接复用已经执行过的 upgrade 或直接切回新镜像。**

   再删除物理列；不能仅因当前没有值就删除。
