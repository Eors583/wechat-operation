# 数据库结构优化（第一阶段）

## 范围和结论

本次核对了线上业务库 56 张表的元数据，并追踪了下表中字段及业务数据的调用代码。库容量目前很小，
本阶段解决数据职责混杂，不作全库拆表、分库或分区。

| 对象 | 本次处理 | 原因 |
| --- | --- | --- |
| 私有用户偏好 | 新增 `user_memory_entries`，切换业务读写 | 从用户级 JSON 数组变为可独立更新的记录 |
| 偏好确认建议 | 新增 `preference_proposals`，切换建议查询和接口投影 | 不再扫描消息正文 JSON 查找业务状态 |
| `user_preferences` | 保留 | 承载显式写作风格等配置，与私有用户偏好不是同一资源 |
| `article_versions` / `article_renders` | 保留不可变内容和版本引用 | 支持历史恢复、预览确认与发布一致性 |
| `library_items` | 保留列表投影 | 不是文章正文的第二个事实来源 |
| `documents.normalized_object_key` | 保留 | 虽然线上当前为空，解析流程仍会写入 |
| `tasks.current_skill_id` | 保留 | 创建会话、技能选择、智能体调用仍在使用 |
| `owner_type` | 保留 | V3 设计明确预留工作空间所有权，不因当前全为 user 删除 |
| `article_renders.html_object_key` | 暂留、候选退役 | 当前 6 个渲染记录均为空，代码只剩模型与注销清理，但仍属于现有 HTTP 契约和 V3 存储设计 |

## 新结构

`user_memory_entries` 的一条记录对应一个用户、一个项目作用域和一个偏好维度：

- `user_id`、可空的 `project_id`、`key`：归属、作用域、维度。
- `value`、`evidence`：偏好内容和用户原文依据。
- `status`、`source_type`：生效/撤销和确认来源。
- `source_message_id`、`confirmation_message_id`、`source_at`：来源追溯。
- `id`、`created_at`、`updated_at`：记录身份和更新时间。

个人作用域对 `(user_id, key)` 建部分唯一索引，项目作用域对
`(user_id, project_id, key)` 建唯一约束，防止 NULL 作用域下产生重复记录。
项目引用不使用 `ON DELETE SET NULL`，避免项目偏好意外变成全局偏好。

`preference_proposals` 使用来源消息 ID 作主键；保存用户、项目、维度、建议内容、
依据、状态、过期时间、建议时间及确认来源。`base` 和 `previous_value` 是确认时的
冲突检测及展示快照，不属于无用重复字段。主键保证一条来源消息只有一条建议。

两张表使用外键、状态约束和与当前查询匹配的索引。账户注销清理同时清理新表。
智能体仅读取本人已确认的生效记录，仍按“当前输入 > 写作风格 > 用户偏好”使用。
同维度项目偏好优先于全局偏好，不向前端提供完整偏好档案。

消息表中的单轮/批次评估进度仍是本轮任务元数据，暂不另建通用工作流表。
确认建议通过接口投影回原有消息响应结构，前端和 OpenAPI 契约不变。

## 迁移与兼容窗口

迁移：`e8c20f7a913b`，前置版本：`d7f93a10bc62`。

1. 在目标镜像交付并准备好后，暂停 API、Worker、Scheduler 的写入，备份业务库。
2. 从目标镜像单独执行 Alembic 升级；创建两张表，回填旧偏好和历史建议。
3. 迁移遇到未知字段、无效日期、重复维度、外键/状态错误或计数不一致时中止事务，
   不静默丢弃旧记录，不切换应用。
4. 持久化目标镜像仓库和版本，再切换三个后端服务，恢复网关。

旧 `user_preference_memories.items` 和消息里的 `preference_proposal` **本阶段仍保留**，
作为上一版应用的回滚副本，新应用在同一事务内同步写入；它们不再是新应用的读取来源。
本阶段不宣称已经删除这些冗余存储，也不删除文章、聊天、发布或审计数据。

应用回滚只切回上一镜像，无需数据库降级。迁移的 downgrade 明确拒绝删除新表。
**如果旧版恢复运行并接收了写入，再次启用新版本前必须暂停写入，从旧副本重新回填并
核对新表；不能直接复用已经执行过的 upgrade 或直接切回新镜像。**

## 后续物理清理条件

待用户完成偏好确认、仅本次、撤销、项目隔离及存草稿/发表触发总结的手动验收，
并确认上一版回滚窗口结束后，使用独立的 Alembic 迁移：

1. 停止兼容双写，删除旧偏好 JSON 表及消息中的兼容建议副本。
2. 对 `html_object_key` 明确选择内联 HTML 或对象存储，并同步退役旧 HTTP 字段，
   再删除物理列；不能仅因当前没有值就删除。

本次按项目规则仅运行后端 Ruff lint，不运行单元测试、集成测试或生产功能冒烟。

## 第二阶段：经业务复核的物理退役

用户进一步明确授权删除已确认不参与现有业务或未被相关页面使用的冗余对象。
逐项复核了后端读写、动态 ORM 接口序列化、前端实际消费、生产数据和外键引用。
这部分取代前述“等待清理”的计划，不扩大到实际使用中的版本、审计或检索表。

| 对象 | 业务依据 | 处理 |
| --- | --- | --- |
| `article_assets` | 空表，无业务读写；文章图片和封面走现有节点/封面引用 | 删除表及模型 |
| `auth_identities` | 空表，仅注销时清空；现有注册和登录查询 users | 删除表、模型及无效清理 |
| `context_snapshots` | 仅写入，无读取；另有 AI 运行快照 | 停止双份写入，新预算并入 AI 运行快照，历史独立归档后删表 |
| `user_preference_memories` | 读取已迁到独立偏好记录，仅剩兼容副本 | 停止双写并删表 |
| `messages.content_json.preference_proposal` | 与新表重复，接口已从新表投影 | 只清除此 JSON 键，保留消息及其他元数据 |
| `job_records.next_retry_at` | 全空，无业务调度或页面消费 | 删除物理列 |
| `article_renders.html_object_key` | 全空，仅清理代码，正文读取 html | 删除物理列，保留 html |
| `tasks.use_preferences` | 生成时强制开启，旧开关不代表实际行为 | 删除物理列及无效开关写入 |
| `user_preferences.confidence` | 当前写作风格不按置信度生效，旧学习函数无调用 | 删除物理列和无调用的学习代码 |
| `ix_ai_events_run_seq` | 与唯一索引 uq_ai_event_seq 同键 | 删除普通重复索引，保留唯一约束 |
| 非 writing_style 的旧偏好行 | 当前创作、查询列表均不消费 | 备份后清理，不自动转为已确认用户偏好 |

保留 `user_preferences.preference_type`：它仍参与现有 API、资源筛选和所有权查询，
不是本次可以直接删除的字段。新建接口只允许 writing_style，避免再写入不可见类型。
提示词、文章版本、发布确认、检索与幂等表保留。

部署分为两个 Git 版本：

1. **兼容版本**：迁移 `f29d7a861ce4` 仅给旧非空列加默认值，应用停止读写所有退役对象。
   老客户端的四个响应字段由 API 层返回兼容值，不再占数据库列；输入旧字段仍可解析。
   这使实际在运行及紧邻的回滚版本都能适应删除后的结构。
2. **清理版本**：必须确认兼容版本已经运行，再备份、归档，显式执行独立删除迁移，
   最后切换到清理版本。禁止跳过兼容版本直接清理仍被旧镜像读取的列。

历史 context_snapshots 共 56 条，其中 3 条按来源消息无法唯一关联 AI 运行。
不得猜测归属或修改已有 AI 运行的冻结输入哈希；这 56 条原记录完整保存在服务器
受限权限的退役归档中，未来数据直接写入 ai_runs.context_snapshot。
归档和完整业务库备份均不进入 Git。恢复时只从备份提取需要的旧对象，不覆盖整个生产库。

清理版本只能回滚到上述兼容版本；不能回滚到仍依赖退役表/列的旧版本。
每次切换都记录完整镜像引用，保留当次及前一版镜像。未自动执行功能测试。

### 清理迁移的执行门槛

兼容应用提交为 `4cf2301`，清理迁移为 `a60e912f4bd8`。执行前确认 API、Worker、
Scheduler 都已使用兼容镜像，暂停写入，保存完整业务库备份以及旧表的独立归档。
服务器归档权限为 `600`，记录 SHA-256，不输出或上传用户记录。

使用清理版本镜像显式执行：

```text
uv run --no-sync alembic -x storage_retirement_confirmed=1 upgrade head
```

该确认参数只应在上述部署和备份条件满足后传入；常规启动不执行迁移。
迁移对受影响表加锁，在同一事务中复核空表、空字段、旧偏好类型、已迁移的偏好
和确认记录，以及必须保留的唯一索引。发现未审计数据、意外依赖或锁等待超时立即
停止并回滚事务，不使用 CASCADE，不修改已有 AI 运行冻结快照及哈希。
历史快照全部归档，不对无法唯一关联的记录猜测 AI 运行归属。

镜像仓库鉴权失败时，发布采用 SHA-256 校验的 SSH 归档回退方式；服务器只加载镜像。
删除后的应用回滚目标为 `wechat-ai-backend:git-4cf2301`，不能切回 `git-b7c7873`。
