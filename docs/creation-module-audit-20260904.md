# 对话创作 → 文章预览：全栈审查

日期：2026-09-04。范围：当前工作区源代码、V3.0 技术设计、现有专项测试与隔离环境复现。此次不修改业务代码、生产配置或用户数据。

## 结论

已有可用的工程基础：版本化技能、资料解析与混合检索、冻结上下文、任务摘要、已确认偏好、文章不可变版本、乐观锁、幂等以及微信最终 Render 确认。但目前是“若干能力分别存在”，不是“技能库 + 文章库 + 历史对话 + 用户反馈持续学习”的完整闭环。

最应先解决的是：预览保存与真正入库脱节、预览编辑丢失风险、跨轮资料丢失、错误偏好自动确认。单纯强化提示词或更换模型无法修复这些链路问题。

## 流程与完成度

| 步骤 | 当前实现 | 评价 |
| --- | --- | --- |
| 1. 输入与资料选择 | 创建任务或追加消息；上传、链接、手动选择 Document | 基础具备；已生成文章不是可选参考，资料未跨轮绑定 |
| 2. 选择技能与上下文 | 手动技能或关键词匹配；本任务最近 20 条消息、最新摘要、当前文章、已确认偏好 | 部分具备；不是跨任务历史召回 |
| 3. 生成 | 意图、规划、正文、内容检查、摘要分阶段调用；结构修复与安全检查 | 基础具备；规则分类优先导致一些自然表达无法正确执行 |
| 4. 文章预览与编辑 | 独立 Tiptap 编辑实例，本地样式模拟模板，手动保存 | 存在保存语义与编辑保护缺陷 |
| 5. 入库与确认 | 完整编辑页的 save-local 入库并派发索引；微信确认触发偏好候选 | 后端具备；创作预览的同名按钮未接通 |
| 6. 总结与习惯学习 | 每轮任务摘要；保存/最终确认时提取字数及 5 类规则偏好 | 范围窄，存在漏学和反向学习，无修改差异分析闭环 |

## 主要发现

### F1 / P1：预览“存本地草稿箱”没有真正入库

- `apps/user-client/src/pages/CreatePage.vue:956` 的按钮只调用预览面板 `saveNow()`。
- `ArticlePreviewPanel.vue:101` → `client.ts:2481` 的 `saveArticle()` 只执行 `PUT /articles/{id}/content`。
- 真正写入 LibraryItem、触发文章索引和偏好学习的是 `app/api/user.py:1737` 的 `POST /articles/{id}/save-local`。
- 完整编辑页 `ArticlePage.vue:660` 已正确地先保存内容，再调用 `setArticleOutcome(local_draft)`；预览没有复用这条流程。

后果：点击同名按钮，用户以为已入库，但新文章可能仍不出现在文章库，也不触发该入口的学习与索引；没有 dirty 时连内容保存都不执行。

建议：复用现有内容保存 + 本地草稿状态提交流程；区分“保存修改”和“存入草稿箱”的语义，不另造第二套保存协议。

### F2 / P1：预览编辑存在两种内容丢失窗口

- `CreatePage.vue:929` 直接双向绑定弹窗显示；`:937` 在关闭时销毁预览实例。通用 `AppDialog.vue` 默认可通过关闭、Esc/遮罩关闭，没有 dirty 检查。
- `ArticlePreviewPanel.vue:145` 卸载只销毁编辑器，未保存、未保留本地草稿、未提示未保存修改。
- `ArticlePreviewPanel.vue:111` 在保存返回时无条件设置 `dirty=false`，而保存过程中编辑器仍可输入。请求发出后新增的修改因此可能被错误标为已保存；下一次保存早退，关闭后丢失。

复现步骤：打开预览修改正文后直接关闭；或慢网下点击保存、立即继续输入、等待保存成功再关闭。

建议：复用完整编辑页已有的 editRevision/saveInFlight、本地草稿及离开保护。`ArticlePage.vue:345` 已有保存快照与后续修改的区分，无须新建复杂编辑框架。

### F3 / P1：文章库索引存在，但创作召回链路不接受文章

- `PromptComposer.vue:171` 只请求 `type: 'reference'`，排除了已生成文章。
- `app/domains/ai.py:367` 只按 Document 表验证输入 ID；没有 Article 参考入口。
- `ai.py:393` 只有显式 document_ids 非空才执行检索。
- `app/retrieval.py:228`、`:525` 对空 ID 列表直接返回，不执行“自动检索我的文章库”。
- `worker_tasks.py:500` 确实索引文章，但目前生成入口无法利用这部分文章索引。

隔离 API 复现：已保存文章的 ID 放入 document_ids，返回 `404 DOCUMENT_NOT_FOUND`。

建议：在现有检索服务中明确支持 document/article 两种受控来源；优先同项目且用户已采纳的最终稿，查询始终按认证用户隔离。不要将所有初稿默认认定为优质范文。

### F4 / P1：资料正文没有跨轮延续；其他任务的历史未召回

- `_resolve_untrusted_references()` 只读本轮 content 中的 document_ids/attachments/links。
- `ai.py:1273` 的 recent_messages 只保存 id、role、text，不携带旧消息附件及资料正文。
- 当前任务查询最近 20 条消息和最新 TaskMemorySummary；新任务没有同项目历史任务摘要或历史对话相关性检索。

隔离 API 复现：第一轮带公开测试链接生成；第二轮仅说“继续优化这篇文章”，冻结上下文的 untrusted_documents 数量从 1 变为 0。新任务 recent_messages 为 0。

这不代表第二轮完全没有上下文：当前文章和任务摘要仍在，但原始参考依据没有保留，后续核查引用、数字与事实会变弱。

建议：保存任务的活动资料集合，并允许用户移除；每轮重新按主题检索，快照记录资料版本和来源。跨任务只召回同用户/合适项目的相关摘要、已采纳修改和最终稿，不无差别注入所有聊天记录。

### F5 / P1：偏好规则会漏学、误学，且可直接污染长期偏好

位置：`app/domains/article.py:448` 的 `upsert_article_preference_candidate()`。

1. `:507` 只读取首个 ArticleVersion 创建时间之后的用户消息，首条写作请求中的长期习惯被排除。
2. `:514` 仅固定匹配 5 类规则（开头、标题、简洁、案例、术语）和篇幅，没有分析编辑前后差异。
3. `:536` 把所有消息拼接后，只要任意位置有“以后”等词，就把所有命中的模式按长期意图处理；否定语义未处理。
4. `:467` 只比较最终内容与第一版哈希；AI 后续自行修改、预览拆离标题也可构成“发生修改”，不能证明用户主动选择了相应风格。
5. `:476` 如果本文章的篇幅偏好已确认或撤销，整段函数提前返回，其他新风格信号也不再提取。
6. 重复跨文章命中可自动 confirmed，但来源仅存单个 source_id；没有完整证据列表、冲突合并或对相反偏好的处理。

隔离 API 复现：

- 首条消息“以后文章开头不要铺垫，请写一篇团队管理文章”，人工改稿并 save-local 后，没有 direct_opening 偏好。
- 后续消息“这篇表达不要简洁，详细一点。以后标题不要夸张。”，人工改稿并保存后，生成 confirmed 的“表达偏好简洁直接”，方向与用户要求相反。

建议：明确表达、人工编辑差异、采纳/拒绝 AI 建议分别记录证据；候选提取使用结构化输出及否定/范围判定。低置信度候选需要用户确认；可自动确认的明确长期要求必须绑定具体句子及作用域。新习惯需处理与旧习惯的冲突，用户可撤销。不学习未采纳的 AI 自说自话。

### F6 / P1：当前文章被静默截断后，AI 仍按整篇替换保存

- `ai.py:1200` 固定分配剩余上下文 25% 给 current_article，并截断 plain_text。
- `ai.py:1760` 之后的文章生成分支使用模型输出创建完整新版本。
- 没有“全文不完整”标记、局部 patch 约束或超长全文改写拒绝。

风险：长文只要求优化结尾时，模型可能未看到结尾；生成结果仍替换整篇，可能漏掉未见内容。这里是代码可达风险，未声称真实模型已实际删文。

建议：全文改写保证完整基线可见，超限时拒绝或改用更大窗口；局部修改按节点/选择范围应用，并保留未修改节点。整包预算还应覆盖提示词、技能、项目要求、摘要、规划以及 JSON 开销，而非仅分配各正文片段。

### F7 / P2：模型识别了意图，但实际操作仍由粗粒度关键词固定

- `classify_run_type()` 在创建任务阶段决定 run_type；提纲/总结匹配发生在完整文章意图之前。
- `ai.py:1571` 模型意图结果只存入 intent_analysis，不改变有效操作及路由。

确定性复现：

| 用户表达 | 当前分类 |
| --- | --- |
| 请写一篇管理文章，先列提纲再写全文 | outline |
| 这个开头不好，换一种说法 | discussion |

后果：自然表达的完整写作或修改请求可能只得到讨论，用户被迫迁就关键词。

建议：模型输出受约束的操作意图，由后端进行授权及状态机校验；明确写作与辅助步骤组合的优先级。涉及覆盖、新任务、发布的确认边界继续保留。

### F8 / P2：自动技能匹配不是完整的场景适配

- `_skill_match_score()` 使用名称/场景/描述中文 n-gram 与阈值匹配，不判断真实语义或模型能力。
- `ai.py:1144` 把自动选择写回 current_skill_id，后续可能作为手动固定技能使用，没有区分 auto/manual 模式。
- 技能正文在正文生成前追加，但规划阶段只拿到 skill_version_id，不含技能 instructions。
- 局部修改 `app/domains/revision.py:128` 使用基础文章、选区与指令，不复用主创作上下文里的技能、偏好、项目要求及引用。

建议：保留一个主技能的 V3.0 约束；显式记录选择模式及原因。让规划、生成、局部修改共享必要的写作上下文和安全约束，避免写作与润色风格不一致。

### F9 / P2：摘要和内容校验不足以证明“越用越专业”

- 每轮会调用 memory_summary，但输入主要是上一份摘要、本轮要求、助手完成说明及文章 ID/版本号，并非最终正文与编辑差异。
- 摘要降级文本仅本轮信息；上一份累计摘要没有合并保留，最新摘要可能丢掉更早事实。
- content_check 只把以 ASCII `FAIL:` 开头的输出视为不通过；`FAIL：`、其他格式或不确定回答可能被当作通过。
- 校验失败目前仅警告，并无质量优化闭环；这可以是产品策略，但不能将其描述为已自动修正错误。
- text.delta 在整篇生成及检查后一次性发出，不是真正逐 token 流式正文；摘要也在最终 article.ready 之前执行。
- 未见以最终采纳率、人工修改量、事实/引用正确率及风格遵循率为核心的跨轮效果回归集。

建议：结构化校验结果；正文完成与非关键记忆任务解耦；用少量固定真实业务案例验证改善，不把调用次数或摘要数量当作质量提升证据。

### F10 / P2：预览模块存在两套编辑与样式逻辑

创作弹窗是 Tiptap + 前端样式变量；完整编辑页还具有自动保存、草稿恢复、冲突处理和后端 Render 预览。V3.0 要求区分编辑视图与真正微信预览，目前创作弹窗把编辑视图称为文章预览，且与完整编辑页能力不一致。

建议：明确标注编辑预览与微信最终效果，微信效果沿用已有服务端 Render；抽取稳定的保存/草稿行为供两处复用，不做布尔参数堆叠的通用大组件。

## 建议的最小闭环

输入本轮目标 → 识别受控操作 → 选择已启用主技能 → 召回活动资料、优质历史文章、相关任务摘要和已确认偏好 → 冻结上下文及预算 → 规划/生成/校验 → 安全预览和版本保存 → 用户编辑、采纳、拒绝或最终确认 → 提取有来源的候选习惯 → 冲突处理/用户确认 → 下一轮实际应用并展示来源。

知识来源需要分层：技能回答“怎么做”，资料回答“事实是什么”，已采纳文章回答“优秀成品长什么样”，历史对话回答“这个用户曾明确要求什么”。外部资料不能自动升级为用户习惯；用户本轮要求优先于历史习惯。

建议在生成结果中提供简洁的“本次参考”信息：主技能及版本、资料/文章名称、应用的习惯、资料不足或截断警告；学习产生候选后，用户能明确看到、修改、拒绝与撤销。

## 修复顺序与验收

1. 先修数据正确性：预览保存真正入库、dirty/关闭保护、跨轮资料保留、否定偏好不误确认、长文修改不丢段落。
2. 再接通复用：Document + Article 统一检索入口、任务资料绑定、相关任务摘要召回、局部修改共享写作上下文。
3. 最后做学习质量：编辑差异、采纳/拒绝证据、候选冲突管理、可见的学习结果及质量回归。

最小验收案例：旧文章能够被实际引用且不越权；第二轮继续使用第一轮资料；用户说“不简洁”不会学成简洁；首条长期要求可追溯；一次性要求不会污染全局；删除/撤销偏好后新运行不再使用；保存期间继续编辑不会被标为已保存；长文局部修改保留全部未选中内容；预览入库只产生一个有效入库结果。

## 本次验证结果与边界

- 用户端 Vitest：12 个测试文件、60 项通过。
- 用户端 vue-tsc：通过。
- 后端选定 9 个专项测试文件：24 项通过、9 项失败。
- 失败主要暴露现有测试夹具与 MockModelProvider 不一致：后者当前直接抛出 ProviderUnavailable，而若干测试仍依赖它返回生成结果；至少一个自定义阻塞模型也继承了该失效行为。不能把这些失败直接归因为生产真实模型故障，也不能视为学习功能已获测试保障。
- 额外通过临时 SQLite + ASGITransport + 显式 AuditModel 的隔离诊断，复现了首条偏好漏学、否定偏好误确认、跨轮参考正文丢失、已保存文章无法作为 Document 参考及规则意图误分类。仅验证上下文/状态/逻辑，不证明真实文章文案质量。
- 本地 http://localhost:9003 可打开，但浏览器处于登录页。按产品审查技能要求，未将旧截图或源代码猜测冒充当前视觉审查证据；此次不提供“完整 UI 验收通过”的结论。
- 创作与预览的 1440×900、1280×720、1024×768、390×844、明暗主题、长内容几何、键盘操作及实际端到端流程尚未验证。
- 未执行全仓 lint/build、全量 pytest、数据库迁移、生产检索库/真实模型调用或微信提交。此次结论为源码与隔离测试审查，不是发布验收。
