# 聊天原文件输入

## 已实现的边界

- 当前支持 Moonshot 官方 `https://api.moonshot.cn/v1` 和 `https://api.moonshot.ai/v1` 的聊天适配器。
- PDF、Office 和文本原文件通过 multipart `/files`（purpose=file-extract）传给官方；读取官方 `/files/{id}/content`，完整内容置于 `untrusted_model_files` 对话上下文，不经本地解析、分块或截断。
- 这是“原文件上传至模型服务 + 官方文件问答”，不是宣称模型原生读取 PDF 页面、图表和版式。
- 其他渠道及图片、音视频明确报不支持，不退回文件名、模拟正文或检索片段。
- 按服务端认证用户检查文件所有权、删除状态、安全检查状态、实际字节数和 SHA256。文件上限 100MB，总正文超上下文预算明确报错。
- 同会话后续追问继承最后一次明确引用的文件，并从同账号同会话同模型服务的历史运行快照复用官方完整内容。不会跨服务默默回退模型。
- 官方文件提取后请求删除远端文件副本，文件 ID 作为交付凭证保存；对话用官方完整结果，不把已删除 ID 当成原生输入句柄。删除请求失败时远端可能留存副本，需服务方运维清理。

## 开发存储

开发环境模拟存储新完成的原文件持久化在后端 `.local/model-file-objects/`（已忽略提交）。Compose 的后端共享挂载使 API 重启后仍能读取这些原文件。生产 S3 通过私有对象读取。

旧版仅存内存、已经因重启丢失的原文件无法恢复，必须重新上传。数据库与原有文章不作迁移、不删除。

## 验证

- tests/test_model_files.py：原字节 multipart 上传、官方正文进入模型请求、空正文拒绝、不支持域名拒绝、文件所有权、后续追问复用、超限拒绝、开发文件重启保留和删除。
- 真实官方联调：上传仅在文件内含随机校验码的 TXT，官方返回全文，Kimi 正确返回校验码。未替用户重复创建文章。
- 参考 https://platform.kimi.com/docs/guide/use-kimi-api-for-file-based-qa

## 仍需注意

本文实现不替换资料库的离线解析索引功能，聊天输入不再使用该模拟正文作为附件内容。开发模拟安全检查不等于生产病毒扫描；生产继续要求真实安全检查通过。
