# 对话中的写作风格操作

对话统一使用现有 `POST /api/v1/tasks/{id}/messages`，通过现有 AI Run / SSE 返回结果。后端识别当前用户的明确操作，将操作和目标冻结到运行上下文，在所属用户范围内执行；模型只负责生成或修改风格内容，不决定资源 ID 或数据库操作。无需额外的意图识别 HTTP 接口。

| 对话示例 | 实际动作 | 对应已有接口 |
| --- | --- | --- |
| 把这个保存成我的技能 | 将上一轮内容创建为已启用的个人技能，不写入风格库 | `POST /api/v1/skills` |
| 总结并保存我的写作风格 | 生成标题和内容，保存为已确认的个人风格 | `POST /api/v1/preferences` |
| 总结这篇文章的写作风格，不要保存 | 仅总结，保留本轮结果供下一轮引用 | 对话接口 |
| 把刚才的保存下来 | 保存上一轮风格总结；重复要求不会重复添加同一份已保存结果 | `POST /api/v1/preferences` |
| 查看我的写作风格 | 从数据库读取当前用户未撤销的风格和状态 | `GET /api/v1/preferences` |
| 修改写作风格《名称》，语气更简洁 | 按明确名称修改完整风格，保留未要求修改的部分 | `PATCH /api/v1/preferences/{preference_id}` |
| 删除写作风格《名称》 | 撤销指定记录，与设置页删除行为一致 | `DELETE /api/v1/preferences/{preference_id}` |
| 确认写作风格《名称》 | 确认为生效，并开启当前任务偏好使用 | `PATCH /api/v1/preferences/{preference_id}`、`PATCH /api/v1/tasks/{id}` |
| 关闭当前任务的偏好学习 / 开启当前任务的偏好学习 | 更新当前任务 `use_preferences` | `PATCH /api/v1/tasks/{id}` |

创建、修改和删除复用设置页 API 的领域函数。操作回执与数据在同一事务中提交；生成失败不保存；修改前目标已变化时不覆盖。运行沿用消息和运行的幂等机制，不重放外部写入。风格明确保存不受自动偏好学习开关阻止，也不自动改变该开关。

名称缺失、同名、批量删除或多个不明确操作会要求用户给出单一目标。上一轮由系统生成的操作元数据用于解析“刚才的”“这个”，不把外部资料当成授权。查看、删除、确认、开关以及直接保存上一轮总结不调用生成模型。

前端在对话正常结束和断线恢复结束时刷新偏好列表。确认风格后，后续创作沿用现有已确认偏好加载逻辑；这不会直接改写当前文章，也不表示其他已确认风格被停用。公众号草稿、正式发布等仍由原有文章工作流执行。

本次仅执行相关项目 lint；未运行功能测试，发布后由用户手动验证。
