# 资料原创分支实现说明

## 适用范围

文章创作意图且存在上传资料、已提取链接正文或明确粘贴的资料时，启用证据驱动生成。已有文章仅在明确要求根据资料创作时进入；局部修改、偏好设置、标题和摘要继续使用原流程。附件结合简单的“写篇文章”或“改写”也能进入创作。

## 本次实现

1. 保留实际读取到的文本、文档/网页来源、已有页码和分块信息，并增加字符位置。缺少页码时不推造页码。原生附件复用模型文件读取通道提取正文，回验基线为供应商提取文本，不能证明与二进制原文件逐字一致。
2. 在任何主题摘要之前逐段抽取原文证据。正则提供数字、引语候选，模型判断相关性及事实/观点/推断属性；正则结果不直接视为可靠事实。证据必须在指定来源逐字匹配；不匹配即停止，不静默丢弃后继续写作。
3. 事实清单绑定大纲。大纲必须覆盖全部 P0 与至少 70% 的事实，不能引用未知 ID；最多补齐一次，仍不合格则停止。
4. 复用原有 Tiptap 正文生成、结构校验、补全与发布格式修订流程，并注入事实约束。原创限于结构和表达，保留数字、主体、条件和观点归属。
5. 在最终正文清理后，用独立提示词和独立调用审计全文及标题。逐事实返回正文原文片段，禁止仅凭 ID 或关键词算覆盖；服务端计算覆盖率。P0 至少 95%、全部事实至少 70%，且审计未发现无依据断言时通过。
6. 审计不通过只允许一次受限修订；要求模型只改相关段落并返回整篇文章，随后重新校验与审计。不通过不创建文章版本，不自动重试保存或结算。
7. 成功运行的 `AIRun.context_snapshot.material_grounding` 保存来源、事实、大纲和审计报告，避免将证据正文写入进度事件或普通日志。后台记忆摘要排除此审计记录。

## 边界和取舍

- 本次落实方案第 14 节的最小路径，没有重写整套解析、分节生成或前端模式选择器，无新依赖、数据库迁移或 HTTP DTO。
- 覆盖率的分母是本次实际读取且抽取的事实，不等同于整份资料的全部事实。事实遗漏和语义误判仍需人工评估，不能承诺“零幻觉”。独立调用复用已冻结的规划路由，不承诺使用不同模型。
- 密度和通用论述比例仅作为诊断指标，不强制不同长度、不同信息量的资料满足相同密度；尚未实现连续照抄检测及引用例外规则，不能承诺非抄袭率。
- 默认采用 95% 的关键事实覆盖门槛；没有增加三种模式的 UI 切换。
- 事实相关调用不经过有损摘要；超过所选模型上下文窗口、160 个资料分段或160条事实时明确停止，要求缩小范围或使用更大窗口。分段抽取增加模型调用和延迟。
- 修订采用完整文档返回协议，段落保留由提示词约束，不是后端按节点进行局部补丁。
- 遵循仓库规则，本次只运行后端 Ruff lint，不创建或运行测试。方案中的准确率、原创新颖度、收敛率和 A/B 数字均未在本项目验证。
