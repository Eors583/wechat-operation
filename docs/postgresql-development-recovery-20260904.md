# PostgreSQL 开发环境数据恢复记录

## 根因与运行约束

旧后端 `Settings` 和 Alembic 配置包含 `sqlite+aiosqlite:///./wechat_ai.db` 默认值，后端 README 也把 SQLite 描述为开发默认数据库。这与 V3.0 文档要求的开发 Compose / PostgreSQL 架构不符。之前把管理端从已停止的本地 9010 服务切换到 Docker 8000 服务，没有同步旧数据，导致模型列表为空。

现已移除开发 SQLite 默认值。开发、预发布、生产服务拒绝非 PostgreSQL 业务数据库；检索配置必须指向独立 PostgreSQL。只有显式 `APP_ENV=test` 的隔离测试可以使用临时 SQLite。禁止将该测试模式用于实际业务服务。

- 统一后端：Docker `backend-api:8000`。
- 业务库：Docker `business-db:5432/wechat_ai`。
- 检索库：Docker `retrieval-db:5432/wechat_ai_retrieval`，pgvector。
- 页面通过 9000 网关或 9003 / 9004 开发代理访问同一后端。
- 本机单独启动后端时必须配置同一套 PostgreSQL 和加密密钥，不得另起数据库。

## 备份与迁移

备份目录：`backups/2026-09-04T01-27-30Z/`，含 `business.dump`、`retrieval.dump`、`manifest.json`、`legacy-wechat_ai.db`。SQLite 快照通过 backup API 创建，完整性检查为 `ok`。原始 SQLite 文件未改动，仅作离线恢复材料，不再连接应用。

使用 `services/platform-backend/scripts/import_legacy_sqlite.py`，先执行事务回滚预演，再执行提交。此工具只插入，不覆盖现有记录；ID 或唯一约束冲突会回滚整个事务，重复导入会被拒绝。源文件只读。源加密密钥通过进程环境传入，不写进脚本或报告。

- 31 张有数据的表，共 986 条原始记录已迁入业务 PostgreSQL。
- 包含 3 个模型、1 条路由、8 个旧用户、1 个旧管理员、15 个任务、3 篇文章、5 个文章版本、38 个模板、44 个模板版本、1 个文档，以及积分、审计和历史执行记录。
