# 微信公众号 AI 运营助手运维与恢复手册

## 1. 环境边界

开发、测试、预发布和生产必须使用不同的 PostgreSQL 实例/数据库、检索数据库、对象存储桶、RabbitMQ VHost、Redis 前缀、模型 Key 与微信第三方平台配置。禁止通过功能开关让非生产环境读取生产数据。

生产配置分为三类：公开配置、普通环境变量和 Secret。Secret 仅在运行时由 Secret Manager/KMS 或 Docker Secret 注入，不写入镜像、仓库、前端 bundle、日志或 Trace。

## 2. 部署与扩缩容

发布顺序固定为后端扩展兼容接口、数据库向前兼容迁移、两个前端升级、数据回填与核验、切换默认、后续版本再清理旧契约。数据库迁移遵循“扩展—回填—切换—清理”，不得在同一发布中直接删除仍被旧应用读取的字段。

API 无状态水平扩展；AI、解析、Embedding、微信和同步 Worker 按各自队列积压、供应商 RPM/TPM、CPU/GPU 和错误率独立扩展。Scheduler 只运行一个逻辑实例，并使用数据库顾问锁或短期 Redis 锁防止重复调度；锁不能代替业务状态。

## 3. 备份

业务数据库和检索数据库至少每日备份，业务库启用持续归档/PITR。对象存储开启版本控制、跨区域复制或等价备份，原始文件不能仅依赖数据库记录。密钥管理、微信平台配置、RabbitMQ 定义与监控告警规则同样需要版本化备份。

本地数据库备份：

```powershell
node scripts/backup-databases.mjs
node scripts/verify-backup.mjs backups/<timestamp>
```

脚本只生成两个 PostgreSQL 自定义格式 dump 和 SHA-256 清单，不会把对象存储伪装成已备份。生产对象存储必须使用云厂商/存储平台的版本、复制与恢复能力单独核验。

## 4. 恢复演练

恢复必须先在隔离环境进行，禁止直接覆盖生产。演练步骤：

1. 创建空业务库、空检索库和独立对象存储桶。
2. 使用 `pg_restore --clean --if-exists --no-owner` 恢复数据库备份。
3. 恢复对象存储并核对原文件哈希、派生物可重建标记和私有访问策略。
4. 运行 Alembic 升级到目标应用版本。
5. 执行用户隔离、文章版本、文章库列表、Render 校验值与微信操作状态核对。
6. 对检索库执行抽样回源；必要时从业务事实和对象存储重建块、全文索引和向量。
7. 记录 RPO、RTO、失败点和改进项。正式上线前以及重大数据库变更后必须完成演练。

## 5. 故障处理

- 模型 429：遵守 `Retry-After`，按路由有限重试后切换已发布备用模型；不重复结算额度。
- 模型鉴权失败：停用部署并告警，不继续用同一凭据重试。
- 文件扫描/解析失败：保留隔离对象和阶段检查点；失败内容不进入 AI 上下文。
- 检索服务失败：降级为权限过滤后的全文检索；权限过滤永不降级。
- 微信 `UNKNOWN`：先按外部 ID 查询或等回调对账，禁止直接重放。
- 草稿已创建但发布失败：复用原 `media_id`，不得再次创建草稿。
- SSE 断开：后台任务继续；客户端携带 `Last-Event-ID` 补发，不重新创建运行或扣额度。

## 6. 监控与告警

最低告警集包括 API 5xx/延迟、认证异常、模型失败率与费用、队列积压/死信、文件扫描与解析失败、Embedding 积压、微信令牌刷新/草稿/发布失败、数据库连接/磁盘/复制延迟、对象存储错误和备份失败。Trace、Metric 与 Log 使用同一请求/运行 ID 关联，同时删除 Authorization、Cookie、完整手机号、用户正文、文件全文和所有 Secret。

## 7. 上线门禁

上线前必须具备正式 HTTPS 域名、企业与备案材料、主/备模型和预算、微信第三方平台与测试/正式公众号、生产对象存储、短信、监控告警、用户协议/隐私政策/版权与 AI 内容说明，以及目标平台的签名和商店账号。缺少任一外部账号时，相应 Provider 只能保持 Mock/disabled，不能把模拟结果报告为生产联调成功。
