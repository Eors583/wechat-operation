# 模型更换与路由配置

入口：管理后台 → AI 配置 → 模型、路由与积分。

## 更换步骤

1. 在“模型配置”添加新模型，填写实际接口、协议、模型 ID 和密钥，完成连接测试。
2. 普通对话/视觉模型点击“容量”，按当前供应商文档填写上下文窗口和最大输出 Token。两者须为正整数，最大输出必须小于上下文窗口。0 表示未配置，不表示无限容量。Manus v2 异步任务协议不强制要求这两个字段。
3. 打开“模型路由”，选择要调整的业务用途，选择新主模型。备用模型为可选项，只按管理员显式配置使用。保存新草稿版本，手动测试后发布。
4. 对旧模型服务的其他用途逐一完成切换。模型列表会显示其正在被哪些生效路由引用；用途下拉框显示是否已配置。
5. 确认旧模型不再被生效路由使用后，停用旧模型。历史路由引用的模型不能永久删除，以保留历史与回滚依据。

发布新路由会在同一事务中停用该用途的旧路由。不要先停用旧路由再配置新路由，否则会留下不可用窗口。运行中任务继续使用已冻结的配置；修改容量只影响之后创建的快照。

## 保护规则

- 正在被生效路由引用的模型不可直接停用、替换连接参数或更换 model ID。先添加新配置并发布替代路由。
- 删除模型不会删除路由、移除备用项或自动提拔其他模型；存在任何路由引用时拒绝删除。
- 普通对话/视觉模型发布新路由前必须补齐容量。已有路由不会因升级被强制撤下。
- 对已上线配置重新执行连接测试，不会因一次失败自动将配置降为草稿。
- 用户明确选择的创作模型不因管理员为其他用途配置备用模型而自动替换。
- 修改模型与路由是数据库中的运行配置变更，不需要重新构建、部署或重启应用。只有接入尚未支持的新协议等程序能力变更才需要改代码。

容量配置只声明应用可使用的上限，不能扩大供应商的真实上下文窗口，也不能解决供应商限流、欠费或协议不兼容。连接测试不等于容量与业务效果验证，应按实际供应商参数配置并由管理员验证使用效果。
