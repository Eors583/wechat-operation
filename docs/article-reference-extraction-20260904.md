# 聊天链接文章提取修复（2026-09-04）

## 原因与调整

原有后端已能抓取网页并将正文持久化为 Document，但仅处理 content.links 和链接附件。
直接粘贴在聊天文字中的 URL 没有进入提取流程，导致模型只收到链接。

- 将聊天内链接、Markdown 链接和链接附件统一送入现有安全抓取流程；重复链接只抓取一次。
- 支持微信短链接后紧跟中文要求，保留长链接的签名查询参数。
- 微信使用正文容器提取；普通 HTML 优先 article/main，排除脚本、导航等内容。
- 保存提取出的正文、标题和来源地址，再将正文放入模型上下文。
- 任一链接读取失败或正文无法完整放入参考预算时，在生成及积分预留前报错；不退回裸链接生成。
- 明确要求智能体使用已经提取的正文，交付实际内容而不是完成通知或本地文件路径。
- 合法 Tiptap JSON 保留为结构化内容，聊天和流式输出改用可读正文。
- 微信重定向逐跳检查域名，限制响应体积，不跟随到其他域名或私网；不绕过验证码和权限控制。

## 使用与边界

直接粘贴文章链接并输入改写、总结或参考要求即可，无需新增环境变量或重新配置微信开放平台。
链接需要公开可读；验证码、登录、已删除文章会返回明确错误，可改为粘贴原文或上传文件。
旧回复和旧文章不会自动重写，需要重新发送包含原链接的要求。
没有新增依赖、数据库迁移或修改数据库连接；开发环境继续使用 Docker PostgreSQL。
